# Imports merge, never replace

TCGplayer's order list shows only the last 120 days (the owner's figure, as `orders-job-unbuilt` records it; the cutoff has not been measured). So this app is the system of record for older orders. A re-import must keep every existing item and all `received` state. It adds new lines and will refresh `tracking` and `name` on a line whose key is already stored. Received marks and every other field of that line are kept. It must never drop an item. The Worker's `POST /ledger` never drops an item either, so a device's write never drops one.

Owner ruling (waiting-page item 89 b, 2026-11-15 13:38 CST) sets the `tracking` refresh, and it is built: the web import calls `mergeItems` in `src/merge-rules.mjs` with `refreshTracking: true`. On a key clash the stored line keeps every field and takes the incoming `tracking`. An empty incoming `tracking` keeps the stored one. A refresh can newly cancel a line, and a canceled line leaves the web header Value (`canceled-orders-leave-the-list`). The Worker's `POST /ledger` and the two-device merge (`mergeLedger`) do not refresh: they keep the stored copy, so a stale device cannot revert a newer `tracking`. The refresh therefore stays on the importing device: it never reaches the stored ledger or a second device, and the owner has not ruled how it should (debt `reimport-refresh-stays-on-device`). Owner ruling (waiting-page item 90, 2026-11-15 13:38 CST, the follow-up to item 89 b) sets the `name` refresh: the web import also passes `refreshName: true`, so a stored line takes the incoming `name` when it differs, and an empty incoming `name` keeps the stored one. The key holds no name (`orderId|itemNumber|vendorProductId`), so it never changes. The reason is the Tally: an old-style name ("Ornn - Fire Below the Mountain (Overnumbered)") now matches the new one ("Ornn, Fire Below the Mountain (Overnumbered)") and the card pools once. A rename on purpose moves a line between Tally groups (`tally-pools-on-the-exact-name`). The import summary counts renamed lines apart from refreshed ones. `mergeLedger` and the Worker do not rename, so the rename stays on the importing device too (debt `reimport-refresh-stays-on-device`).

The native client has no CSV import (`csv-import-stays-web`).
