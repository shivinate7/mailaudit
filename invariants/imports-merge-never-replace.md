# Imports merge, never replace

TCGplayer only serves ~120 days of history. So this app is the system of record for older orders. A re-import must keep every existing item and all `received` state. It adds new lines and will refresh `tracking` on a line whose key is already stored. Received marks and every other field of that line are kept. It must never drop an item. The Worker's `POST /ledger` never drops an item either, so a device's write never drops one.

Owner ruling (waiting-page item 89 b, 2026-11-15 13:38 CST) sets the `tracking` refresh, and it is built: the web import calls `mergeItems` in `src/merge-rules.mjs` with `refreshTracking: true`. On a key clash the stored line keeps every field and takes the incoming `tracking`. An empty incoming `tracking` keeps the stored one. A refresh can newly cancel a line, and a canceled line leaves the web header Value (`canceled-orders-leave-the-list`). The Worker's `POST /ledger` and the two-device merge (`mergeLedger`) do not refresh: they keep the stored copy, so a stale device cannot revert a newer `tracking`. The native client has no CSV import (`csv-import-stays-web`).

**Pinned by:** 57.1 to 57.13 and 57.16 (a CSV re-import keeps every line and received mark), 57.14 to 57.15 and 57.18 (a re-import refreshes `tracking` and an empty status keeps the stored one), 33.1 and 33.20 (`mergeItems`, the union the CSV import calls), 33.54 to 33.65 (the refresh changes only `tracking`, counts it, and `mergeLedger` never refreshes), and worker test 4.3 (the Worker merge keeps items from both sides).
