A failed check-in stays on the row that failed

Designer kind: directed · Direction: inline: the failure lives on the row that failed, with a retry on that row

Three concepts, each in both Duo poses (folded first) and on a large phone, plus three add-ons. Every frame is live: set "Next tick fails", tap boxes, or run a fast mail day. Light theme only: the native app is held to light. The same ItemLine draws Packages, Tally and Card in Hand lines, so each concept lands on all three at once.

Today

A failed save leaves the row as it was and shows one line that names no card. The next good tick on any row clears that line (PackagesModel.checkIn sets checkInError = nil), so at speed the one sign is gone before the eye reaches it. Run a fast mail day below: the third tick fails, the fourth wipes the bar.

Struck box: the box you tapped is the retry

The failed row turns red-soft with a red lead bar. Its box draws a dashed red edge and a turn arrow, and the detail line reads "Not saved. Tap the box again." The thumb is already on that box: one more tap writes the same count, because a failed save left the stored count as it was. Other rows' saves leave the mark alone. Only that row's own good save clears it.

Retry at the row's end

The box keeps showing what is stored, so an unticked box means "not in". The price slot gives way to a red Retry button on the row, at the thumb's side. The detail line says "Not saved" and the time of the tap. Retry writes the count the failed tap meant, so it is the same act whichever way the box sits.

Pencil until sent

"I never know if it actually took" covers two cases. A save on the phone can fail (rare), and a saved tick can wait for signal before the sync server has it (common at the mailbox). Here every tick shows both on its own row: a dashed green box is saved on this phone and not yet sent; it sets to solid green when the server has it. A failed save is the Struck box. The running head says the count once; the rows say it by shape.

Edge pointer (add-on to any concept)

When the failed row scrolls out of view, a red pointer floats at the list's edge on the side where the row went. It carries the struck box face and an arrow, not words: the save slot already says "1 not saved" once (ux-label-once), and VoiceOver reads "Show the row that did not save". A tap scrolls the row back to the middle of the list. It is an overlay, so nothing moves, and it goes when the row is fixed or back in view.

Rides along (add-on, Card in Hand)

On Card in Hand the next typed card swaps the answer page to a new envelope, and the failed line would leave with the old one. Here it rides along: it sits above the new envelope's lines under "From Gamma Cards", with its own retry, until it saves or its envelope comes back. It is placed while the page is being redrawn for the new card, and the finger is on the keys then, so no row moves under a press.

Error haptic (add-on to any concept)

The person ticks without looking. A failed save plays the system error haptic (.sensoryFeedback(.error, …)) at the moment the box turns red, so the hand learns of it before the eye. A good save stays silent, as today: hundreds of success taps would numb the signal. Set "Next tick fails" and tap: the frame marks where the haptic plays.

Failures with no single row, and the Tally spread

Not every write has a row. Mark all received and Clear check-ins write a whole package; the stamped filter reads the list. Each failure stays on the control that was pressed, in that control's own row (ux-answer-at-press). Drawn with Struck box; the other concepts read the same.
