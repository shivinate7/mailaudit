Today

On Packages, a failed save shows a footnote bar in the system font on material at the bottom (PackagesView.swift, overlay checkin-error). It names no card. The masthead slot says "couldn’t save", but the masthead has scrolled away. The next good tick on any card clears the bar (PackagesModel.checkIn, checkInError = nil), so in a fast run the only sign lasts one tap. Try it: fail one tick, then tick another card.

Marked line

The quiet concept. The line that failed stays marked until that same line saves: red fill, a red box with "!", and a red bar in the line's leading pad. A good tick on another card does not clear it. The running head, which stays pinned while the list scrolls, holds a count, "1 not saved". A tap on the count opens the list of missed cards, each with Tick again. To redo in place, tap the red box again: it is the same tap that failed. An error haptic marks each miss, so a person who is not looking still feels it.

Returned slip

The bold concept. A miss is returned mail. The failed tick is written in red and drains from the box, and a slip lands above the tab bar, in the thumb's reach. The slip names the card and its seller, and holds Tick again. It stays while any tick is not saved; a good tick on another card leaves it. Tick again redoes the named card where it is, so the list and its scroll do not move. With more than one miss, the slip names the newest and counts the rest; a tap on its words opens the list. The line keeps the same mark as in Marked line.

Large phone

No size is written for the large phone (layout.py devices gives none; Apple's layout page of 2026-11-21 holds no device table). Each frame is drawn at the brief's folded size, 466 x 678 pt, as a stand-in. A taller screen shows more lines; the parts do not change.
