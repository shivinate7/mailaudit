Notes
  1. Source: docs/ideas/plans/trust.md, section "Phase 2: import-receipt, fleshed out". Nothing else in the repo was read for this page, so colours, type and layout are this mockup's own and not the app's tokens.
  2. Frame size: each screen is drawn at 390 x 844 CSS px. The device list gave no size for any device (all sizes null) and the brief gave none, so the size is this mockup's choice. The status bar (54 px) and home indicator (34 px) heights are approximate frame chrome, not figures from an Apple page.
  3. Apple pages read 2026-11-21 (each answered 200): Sheets (Cancel on the leading edge, Done on the trailing edge, grabber, detents), Typography (Large default: Large Title 34/41, Title 3 20/25, Headline 17/22, Body 17/22, Callout 16/21, Subhead 15/20, Footnote 13/18, Caption 1 12/16, Caption 2 11/13), Accessibility (iOS default control 44x44 pt), Buttons (hit region at least 44x44 pt), Layout (respect safe areas; lay out by size class).
  4. Counts: New + Already here + Looks doubled + Differs always equals the lines in the file. "Add anyway" does not move a line out of Looks doubled; it adds it to the Add total. So the Add button reads New + flipped doubles, and Done and Undo read that same total.
  5. Beyond the plan's listed states: the New and Already here lists, the extension receipt with Differs 2 (shows the source label and the "keep held data" rule), and the after-undo screen.
  6. Where the recent-checks log sits in the app was not read. It is drawn here as a "Recent checks" section on Packages (folded) and as the right screen (unfolded).
  7. Not shown, because they are data rules rather than screens: the line fingerprint, the import tag and its sync, and the open status of invariant saved-state-shape. The undo time limit shows only as a caption on the log entry.
  8. The undo confirmation is an in-app sheet. The page uses no native dialog (invariant no-native-dialogs). The undo banner floats above the tab bar and never pushes rows down (invariant no-layout-shift-under-pointer).
