7 · Laptop pose

The top page stands and only shows. It reads at arm's length, so its type is large. Every touch is on the flat bottom page: the query, the hit, the count and the keys.

8 · Held tall, pages stacked

Same stack as the laptop pose: answer on top, query and keys below. Held in the hand, the top page is in reach, so its counts are buttons again and the type is normal.

9 · The other tabs on the open Duo

One rule: a tab spreads when it has a list and a thing you open from it. The list goes left, the opened thing goes right. A row tap changes the right page only. Tally, Orphaned and Ledger all have both, so all three spread. With no fold reported, each stays one page, as today.

10 · Two keyboard cases

Which case is real is unmeasured. Degen measured the system tab bar at 29–71% of the inner width. Nobody has measured the keyboard. Case A: the system keys stay inside the left page. Case B: the system keys span the fold. B's answer is drawn two ways. B1 is an in-app key pad on the left page. B2 lets the system keys span, and moves the query down to sit on them.

Pick: build for A. If B is real, take B1, with a System keys key that switches to B2. B1 loses autocorrect, dictation, swipe typing and other keyboards. It must label every key for VoiceOver. Autocorrect matters least here: card names are not dictionary words, and B1's top row offers open-order names instead. B1 keys are 42 pt wide, under the 44 pt floor. Their height is 44 pt.

11 · The tab bar on two pages

Degen puts a custom 4-tab bar under the left page. Here the keys use the left page, so the bar has three places to go. Each is drawn while typing.

Pick: a, under the right page. It never moves when the keys rise or fall, and it shows on every tab. It loses degen's place, so the two apps differ. Next card moves to the return key.
